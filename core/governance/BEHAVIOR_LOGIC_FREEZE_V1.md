# XiaoE Behavior Logic Freeze v1

Status: ACTIVE GOVERNANCE
Purpose: Protect XiaoE Behavior Logic as the immutable behavioral root.

## Frozen Root

The following file is frozen:

`core/behavior/XIAOE_BEHAVIOR_LOGIC_V1.md`

This file is XiaoE's behavioral root and must not be changed by normal capability growth, refactoring, compression, startup simplification, project work, or architecture cleanup.

## Default Rule

**Behavior Logic is immutable by default.**

All future XiaoE evolution should occur around it through Core architecture, capability modules, routers, project protocols, runtime orchestration, memory, diagnostics, tests, or automation.

Do not edit Behavior Logic merely to:
- simplify another layer,
- remove duplication elsewhere,
- add a new feature or capability,
- optimize startup/runtime flow,
- accommodate one project,
- encode a temporary incident lesson,
- make a cleaner architecture possible.

## Root Preservation

The frozen Behavior Logic includes XiaoE's execution constitution and behavioral anchors such as:
- FACT FIRST
- OWNER FIRST
- SCOPE FIRST
- STABLE PATH LOCK
- ONE CHANGE AT A TIME
- RE-VERIFY
- STOP & REASSESS

These principles remain authoritative even when surrounding architecture evolves.

## Change Exception

A change to Behavior Logic is not part of normal maintenance.

If a future change is ever proposed, it requires all of the following before implementation:
1. explicit user instruction specifically authorizing a Behavior Logic change,
2. evidence that the current Behavior Logic itself is wrong, contradictory, unsafe, or materially incomplete,
3. a dedicated isolated PR affecting Behavior Logic only or the smallest unavoidable supporting scope,
4. a before/after capability and regression review,
5. explicit confirmation that preserved behavioral anchors do not regress.

General instructions such as `继续`, `优化`, `精简`, `升级`, `重构`, or project-level feature requests do not authorize changes to Behavior Logic.

## Architecture Rule

`Behavior frozen -> evolve around it.`

The surrounding system may become simpler, more capable, more automated, or more general, but the behavioral root remains stable unless the explicit exception process above is satisfied.
